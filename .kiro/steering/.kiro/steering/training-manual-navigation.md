# WADEPS Training Manual Navigation and Table of Contents Rules

## Purpose

This steering document controls the structure, table of contents, chapter cards, PDF page references, chapter navigation, and heading hierarchy for the WADEPS Reporting Tool Training Manual web version.

The goal is to convert the completed accessible PDF and Word document into a readable, task-based, digitally accessible WordPress training manual.

The web version must be easy to use for:

* Law enforcement officers
* Supervisors
* Agency administrators
* Users who are comparing the website with the downloadable PDF
* Older users
* Low-vision users
* Keyboard-only users
* Screen reader users
* Users who need larger text and simple navigation

Do not rewrite, simplify, summarize, or change the training manual wording unless the user explicitly asks for wording changes.

The task is to preserve the manual content while improving navigation, readability, accessibility, and ease of use on the website.

---

# Core User Experience Model

Use Option A:

1. Create one main Training Manual landing page.
2. Display chapter cards on the landing page.
3. Each chapter card links to a separate chapter page.
4. Each chapter page includes an “On this page” jump list.
5. Every chapter card includes a PDF page range.
6. Every subsection jump link includes the exact PDF starting page.
7. Every chapter page includes previous chapter, next chapter, and back-to-top navigation.

Do not create one giant page containing the entire manual unless explicitly requested.

Do not make every small PDF subsection a top-level WordPress page.

# Chapter Card Rules

Every chapter card on the landing page must follow this format:

Chapter [number]
[Chapter title]
PDF pages [start]–[end]
[One short task-based description]
Open Chapter [number]: [Chapter title]

Example:

Chapter 7
Batch Upload Process
PDF pages 56–94
Use this chapter to upload multiple use-of-force records using the batch upload template.
Open Chapter 7: Batch Upload Process

Chapter cards should be visually large enough for older users and low-vision users.

Recommended design rules:

* Use clear spacing between cards.
* Use a readable font size.
* Use strong contrast.
* Do not place dense text in small cards.
* Do not rely on icons alone.
* Keep the chapter number visible.
* Keep the PDF page range visible.
* Use descriptive button text.

# PDF Page Reference Rules

PDF page references are secondary metadata.

They help users match the website to the downloadable PDF.

PDF page references must not replace descriptive section names.

Correct:

Incident Information — PDF p. 21

Incorrect:

PDF p. 21

Correct:

Chapter 6: Create a Record
PDF pages 17–56

Incorrect:

PDF page reference pending confirmation

Do not use the phrase “PDF page reference pending confirmation” in final published content.

Use “PDF p.” for single subsection references.

Use “PDF pages” for chapter ranges.

Examples:

* PDF p. 17
* PDF pages 17–56

---

# Navigation Rules for Older Users and Accessibility

The navigation must be easy to scan and easy to use.

Use:

* Large clickable areas
* Clear chapter titles
* Plain-language descriptions
* Consistent placement of page references
* Previous and next chapter links
* Back-to-top button
* Breadcrumbs
* Visible keyboard focus states
* Strong color contrast
* Adequate spacing between links
* Descriptive link text

Avoid:

* Tiny links packed close together
* Long walls of text
* Navigation that only appears on hover
* Color-only meaning
* “Click here”
* Hidden page references
* Multiple competing tables of contents
* Duplicate navigation patterns on the same page

## Chapter Title and Intro Box Rules

Chapter titles should be task-based whenever possible.

A good chapter title should help the user understand what they are trying to do, not just what topic they are reading about.

Prefer action-based titles such as:

* Log In and Set Up Your Account
* Navigate the WADEPS Portal
* Determine Whether a Use of Force Is Reportable
* Understand the UOF Reporting Workflow
* Create a Record
* Complete a Batch Upload
* Review and Approve Reports
* Complete Administrative Follow-Up
* Upload CAD Data

Avoid overly broad or passive titles when a clearer task-based title is available.

Examples:

Preferred:

`Chapter 4: Determine Whether a Use of Force Is Reportable`

Avoid:

`Chapter 4: Understanding Reportable Uses of Force`

Preferred:

`Chapter 8: Review and Approve Reports`

Avoid:

`Chapter 8: Supervisor Review`

Each chapter page should include a short introductory paragraph that explains the purpose of the chapter in plain language.

Use this pattern:

`Use this chapter to [task/action] so you can [outcome].`

Example:

`Use this chapter to decide whether a use-of-force event must be reported to WADEPS based on injury severity, force type, and the WADEPS Reporting Decision Tree.`

Each chapter should also include an “In this chapter” box near the top of the page.

The “In this chapter” box should:

* Use plain language.
* List 3 to 5 learning or task outcomes.
* Avoid long paragraphs.
* Use bullet points.
* Avoid repeating the full table of contents.
* Help users quickly decide whether they are in the right place.

Example:

`In this chapter, you will learn how to:`

* `Identify injury-based reporting requirements.`
* `Identify force-type reporting requirements.`
* `Use the WADEPS Reporting Decision Tree.`
* `Recognize when an event is not reportable.`

Do not include tasks in a chapter if they belong to another workflow chapter.

For example, do not place “Document months with no reportable use-of-force events” in Chapter 4 if Chapter 4 is focused on determining whether an event is reportable.

Instead, use a cross-reference callout:

`Need to report a month with no reportable use-of-force events? Go to Chapter 8: Review and Approve Reports, PDF p. 101.`

Use cross-reference callouts when a related task belongs somewhere else in the manual.

Cross-reference callouts should:

* Be short.
* Use descriptive chapter names.
* Include the PDF page number.
* Help users move to the correct workflow without duplicating content.

# Heading Rules

Use semantic headings in order.

Recommended structure:

* H1: Chapter title
* H2: Major section
* H3: Task, screen, or form section
* H4: Field name, option group, or definition group

Do not use headings only to change visual size.

Do not skip heading levels for styling.

Do not use H4, H5, or H6 for content that should be H2 or H3.

Do not use custom Nexter or WADEPS heading blocks.

Use standard WordPress heading blocks.

---

# WordPress Block Rules

Use standard WordPress blocks whenever possible:

* Heading block
* Paragraph block
* List block
* Table block
* Image block with alt text and caption
* Group block only when needed for layout
* Column block only when the layout remains responsive and readable on mobile

Do not use broken custom Nexter heading blocks.

Do not create custom heading patterns that output the wrong semantic heading level.

Do not paste a full HTML document into a WordPress page.

If HTML is used, paste body content only.

Do not include:

* DOCTYPE
* html
* head
* title
* body wrapper that overrides the WordPress page structure

---

# Callout Rules

The manual uses callouts such as:

* Troubleshooting Tip
* Important
* Important Note
* Guidance for Verification
* Reminder
* Note
* Need Help?
* Example
* Tips
* Next Step
* Status
* Decision

All callouts should use the same base style.

The only required visible emphasis border should be the dark green border on the left side.

Do not place a dark green border around all four sides.

Do not rely on color alone to communicate the callout type.

Always preserve the visible text label.

Correct:

Important
If you are affiliated with multiple law enforcement agencies, please ensure that the correct agency is selected before selecting Create a Record.

Incorrect:

A green box with no visible label.

---

# Link Text Rules

All links must describe where they go.

Correct:

* Open Chapter 6: Create a Record
* Jump to Incident Information
* Download the WADEPS Reporting Tool Training Manual PDF
* Return to Training Manual Table of Contents

Incorrect:

* Click here
* Read more
* Learn more
* Open
* More

For links that open a PDF, include PDF in the link text.

For links that open a new tab, include visually hidden text or visible text indicating that behavior.

---

# Mobile Rules

The manual must be readable on mobile.

On mobile:

* Chapter cards should stack vertically.
* On-this-page navigation should appear near the top of the chapter.
* Avoid side-by-side columns for dense text.
* Avoid tiny PDF page labels.
* Keep touch targets large.
* Keep spacing generous.
* Do not require horizontal scrolling.

If a table is too wide on mobile, convert it to stacked cards or ensure it is horizontally scrollable with clear visual indication.

---

# Accessibility Rules

All chapter navigation must be keyboard accessible.

All links must have descriptive text.

Use visible focus states.

Do not rely on color alone.

Maintain strong color contrast.

Images must keep alt text and captions from the completed Word document.

Tables must have clear headers.

Use semantic lists for the table of contents and on-this-page navigation.

Use aria-labels only when needed. Prefer visible text first.

PDF page references should be visible text, not hidden metadata.

---

# Content Preservation Rule

The PDF and Word document are already complete and accessible.

Do not alter the training manual’s instructional wording unless the user explicitly requests an edit.

Do not change definitions.

Do not rewrite legal or policy language.

Do not shorten procedural steps unless the user asks for a condensed version.

Do not change the order of content inside a chapter unless the user explicitly asks.

The task is to move the content into a readable, accessible WordPress structure.

# Final Implementation Checklist

Before publishing a Training Manual page, confirm:

* The page has one H1.
* Headings follow a logical order.
* The chapter has a PDF page range.
* Every jump link has a matching PDF page number.
* Link text is descriptive.
* Breadcrumbs appear below the page title.
* Previous and next chapter links are present.
* Back-to-top navigation is present.
* Callouts use the approved left-border style.
* Images have alt text and captions.
* Tables have clear headers.
* The page works with keyboard navigation.
* The page is readable on mobile.
* The manual wording has not been changed without approval.
